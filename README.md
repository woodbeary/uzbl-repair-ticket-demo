# UZBL repair ticket demo

A standalone demo of bulk repair-ticket intake for the UZBL portal. A school sends its repair list in whatever format it already has, and the demo turns it into repair tickets. It uses **fake data only** (a fictional district, "Pinecrest Valley USD (Demo)") and does not connect to any UZBL system.

> **Building this into the UZBL portal? Start with [INTEGRATION.md](INTEGRATION.md).**

## What it does

1. **Scan or upload a repair list.** Drop in an .xlsx, .csv, PDF, Word file, a screenshot, or pasted text such as an email.
2. **Pull out the facts.** It finds the header row, works out what each column holds, drops student-name columns, and extracts each device's serial, asset tag, model, what happened, when, where and ship-to address, each with a confidence score.
3. **Ask "What happened?" when something is missing.** If a row has no description, or only something like "broken", the review screen asks for it instead of guessing.
4. **Pre-check claims.** Plain-code rules check each device before anything is submitted: inventory match (with "did you mean"), PO box ship-to, duplicates, missing details, beyond-economical-repair risk, Break-Fix credits, and routing to the warranty claim, the OEM warranty or Break-Fix.
5. **Review screen.** One short question per problem, the suggested fix pre-selected, one tap to accept, then submit every device at once.
6. **Track repairs.** After submit, each new repair appears in a tracker (also at `/track/<id>`) that shows its status and history, and stops to ask when something needs the school (a PO-box label failure, a denied claim, a beyond-economical-repair decision).

The root route (`/`) opens straight on the upload screen.

## How it works

| Step | What runs |
|---|---|
| Read the file | Built-in readers for .xlsx and .csv. Workers AI Markdown Conversion for PDF, Word, .xls, .ods and .numbers. A vision model (`@cf/meta/llama-4-scout-17b-16e-instruct`) reads screenshots. |
| Map the columns | Clef (`@cf/cloudflare/clef`) decides what each column holds. Student-name columns are dropped before any later model call. |
| Extract each device | Clairic (`@cf/cloudflare/clairic`) returns typed fields with confidence, once per row. |
| Judge each device | Clef: damage type, accident vs. defect vs. intentional, in a case or not, and whether the note says what happened. |
| Pre-check | Plain-code rules in `src/shared/rules.ts`. |

If a model call fails, keyword fallbacks in `src/server/ai/mock.ts` take over and the screen says so.

## Stack

Next.js 16 (App Router), React 19 and Tailwind 4, running on Cloudflare Workers through OpenNext. `fflate` reads .xlsx files. Vitest for unit tests, Playwright for end-to-end tests.

## Run it locally

Requires Node 22+.

```sh
npm install
npm run preview   # builds and serves http://localhost:8788 using the keyword fallback (no Cloudflare login needed)
npm test          # unit tests
npx playwright test   # end-to-end tests, against the running preview (Node 22+)
npm run samples   # regenerate public/samples/* (needs Python 3 with openpyxl)
```

`npm run preview` uses `wrangler.dev.jsonc`, which sets `DEMO_AI=mock`, so no model access or keys are needed. To call the real models, use `wrangler.jsonc` with a Cloudflare account that has Workers AI enabled.

## Configuration

There are no keys in the code. Model access comes from the Cloudflare Workers AI binding. See `.env.example` for the variables; copy it to `.dev.vars` for local overrides. Never commit real values.

| Name | Type | Purpose |
|---|---|---|
| `AI` | Workers AI binding | Model calls |
| `AI_GATEWAY_ID` | Variable | AI Gateway that model calls go through |
| `DEMO_AI` | Variable | Set to `mock` to use the keyword fallback instead of Workers AI |
| `INTAKE_LIMITER` | Rate-limit binding | Limits uploads (10 a minute) |
| `ASSETS` | Assets binding | Static files |
| `DEMO_KV` | KV binding | Per-visitor demo storage. Demo only |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | Environment | Only for deploying from CI |
